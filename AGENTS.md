# Repository Guidelines

## Project Structure & Module Organization

Crissanno is a Qt 6.8 / Qt Quick annotation UI. The active entry point is `CrissannoContent/ui/Annotation.qml`, with its declarative form in `AnnotationForm.ui.qml` and shared top-bar component in `AppTopBar.qml`. Keep visual declarations in `.ui.qml` files and interaction logic in the paired `.qml` file. `Crissanno/` contains reusable QML types, constants, simulator data, and `qmldir`. `Python/main.py` launches the application through PySide6; files under `Python/autogen/` are generated by Qt Design Studio and should not be edited manually. Sample dataset images live in `Images/`; resource packaging is defined by `Crissanno.qrc`.

## Build, Test, and Development Commands

Run these commands from the repository root unless noted:

- `python Python/main.py` launches the current QML entry point for local development.
- `cd Python; pyside6-project run` runs the PySide project described by `Python/pyproject.toml`.
- `cd Python; pyside6-project build` regenerates/builds project resources for deployment.
- Open `Crissanno.qmlproject` in Qt Design Studio to edit and preview `.ui.qml` forms safely.

PySide6 and a compatible Qt 6.8 installation are required; no dependency lockfile is currently committed.

## Coding Style & Naming Conventions

Use four-space indentation in Python and QML. Follow PEP 8 in Python: `snake_case` functions and lowercase module names. In QML, use `PascalCase.qml` for components, `camelCase` for ids/properties/functions, and `onSignalName` for handlers. Keep braces on the declaration line, use `readonly property` for immutable design tokens, and wrap user-facing text with `qsTr()`. Preserve the declarative-only restrictions documented at the top of `.ui.qml` files.

## Testing Guidelines

No automated tests or coverage target currently exist. Before submitting UI changes, launch the app and manually verify startup without QML warnings, window resizing, image navigation, drawing/moving boxes and polygons, zoom/pan, selection, locking, delete, and undo/redo. If adding tests, place Python tests in `Python/tests/` as `test_*.py`; place QML tests in `tests/qml/` as `tst_*.qml`.

## Commit & Pull Request Guidelines

Git history is not available in this checkout, so use concise imperative subjects such as `Fix annotation scaling on resize`. Keep commits focused. Pull requests should describe the behavior change, list manual verification steps, link relevant issues, and include screenshots or a short recording for visible UI changes. Call out edits to generated resources or sample images explicitly.
